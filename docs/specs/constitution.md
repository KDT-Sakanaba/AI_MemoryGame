# Constitution（プロジェクト共通原則）

- 最終更新日: 2026-11-24
- 既存ルールとの関係: 既存ルールファイルなし。ここが唯一の原則。

## 1. 開発原則
- 仕様→設計→タスク→実装の順で、小さく作って確認する。
- 不明点は推測で確定せず、その場で質問する（MySpecKit common.md 準拠）。

## 2. 設計方針
- Unity 公式推奨の構造（シーン・プレハブ・スクリプトを Assets 配下に整理）。
- ゲームロジック（カード状態・マッチ判定）を UI 描画から分離する。

## 3. 品質基準
- 完了 = コンパイルエラーなし + 受け入れ条件の動作確認（Play モードでユーザー確認）。
- ロジック部分（マッチ判定・山札生成）は EditMode テストで確認できる形にする。

## 4. 禁止事項
- `.meta` の削除・GUID 変更、生成物（Library/ 等）の編集。
- 仕様に `[要確認]` が残ったままの実装開始。

## 5. 対象ごとの追加原則（任意）
（単一プロジェクトのためなし）
